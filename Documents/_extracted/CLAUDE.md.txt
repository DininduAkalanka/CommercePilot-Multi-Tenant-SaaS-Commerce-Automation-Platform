Core Principles
Always prefer:
Readable code
↓
Maintainable code
↓
Testable code
↓
Performant code
↓
Concise code
Never sacrifice architecture for convenience.
Architecture Rules
Follow Clean Architecture.
Controllers contain no business logic.
Business logic belongs in services.
Domain models contain business rules.
Repositories access databases.
External APIs belong inside adapters.
Never bypass architectural layers.
3
Multi-Tenant Rules
Every business is a tenant.
Every request must include tenant context.
Never query data without tenant filtering.
Cross-tenant access is forbidden.
Tenant isolation is mandatory.
AI Rules
AI never makes business decisions.
AI recommends.
Humans approve.
Never allow AI to create orders without approval unless explicitly enabled.
Always calculate confidence.
Always use product retrieval before extraction.
Never hallucinate products.
Database Rules
Never change schema unless task requires it.
Always create migrations.
Never delete production data.
Use UUIDs.
Soft delete wherever applicable.
Add indexes when needed.
Use transactions for critical operations.
4
API Rules
REST only.
Version APIs.
Validate all input.
Return consistent error responses.
Never expose internal exceptions.
Document every endpoint.
Security Rules
Validate every request.
Sanitize input.
Never trust client input.
Encrypt secrets.
Use RBAC.
Log authentication failures.
Never expose sensitive information.
Coding Standards
TypeScript strict mode.
No any type.
No duplicated logic.
Meaningful naming.
Small functions.
Small classes.
5
Dependency Injection.
Single Responsibility Principle.
SOLID.
Error Handling
Every operation must:
Handle expected failures.
Log unexpected failures.
Return meaningful messages.
Never swallow exceptions.
Retry transient failures.
Logging
Use structured logging.
Every request has:
Request ID
Tenant ID
User ID
Correlation ID
Never log secrets.
Testing
Every feature requires:
Unit tests
Integration tests

Validation tests

Performance
Avoid N+1 queries.
Use pagination.
Use indexes.
Avoid unnecessary API calls.
Queue long-running jobs.
Cache where appropriate.
Measure before optimizing.
Documentation
Every implementation must update:
API documentation
Architecture documentation
Changelog
Task status
Technical decisions if necessary
Git Rules
Small commits.
Clear commit messages.
One feature per branch.
Do not mix unrelated changes.
7
Code Generation Rules
Never generate placeholder code.
Never generate TODO implementations.
Never fake APIs.
Never fake database models.
Never ignore compiler errors.
If implementation cannot be completed because context is missing:
STOP
Explain why.
Request the missing information.
Definition of Done
A task is complete only if:
Business requirements satisfied.
Architecture respected.
Tests pass.
Documentation updated.
Logging implemented.
Validation implemented.
Security reviewed.
No critical lint errors.
No duplicated logic.
Code ready for production.
8
Communication Style
When implementing:
Explain important decisions.
Mention trade-offs.
Highlight security concerns.
Highlight performance implications.
Suggest improvements.
Challenge bad design decisions politely.
Never blindly implement poor architecture.
Recommend production-grade alternatives.
Final Principle
CommercePilot is not a university demo.
Build every feature as if it will serve thousands of businesses in production.
Every line of code should be something you would be proud to deploy to a paying customer .
