1. Purpose
This document defines the API standards for CommercePilot.
Every API must follow these rules.
Consistency is mandatory.

Correct

/products
/customers
/messages
Incorrect

/createOrder
/productList
Use lowercase.

6. Standard Response Format
Success
{ "success": true, "message": "Order created successfully.", "data": {}, "meta": {} }
Failure
{ "success": false, "message": "Validation failed.", "errors": [] }
Never return inconsistent response structures.
7. HTTP Status Codes
200 OK
201 Created
204 No Content
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
409 Conflict
422 Validation Error
429 Too Many Requests
3
500 Internal Server Error
Never return 200 for failures.
8. Pagination
Large collections must use pagination.
Request
GET /orders?page=1&limit=20
Response
{ "success": true, "data": [], "meta": { "page":1, "limit":20, "total":250, "totalPages":13 } }
Never return thousands of records in one request.

15. Authentication
JWT required.
Authorization Header
Bearer <token>
Never accept authentication in query parameters.
16. Authorization
Every endpoint must verify:
Authentication
Role
Tenant
Permissions
Frontend checks never replace backend authorization.
17. Multi-Tenant Rules
Every request belongs to exactly one tenant.
Every database query must filter by tenant_id.
6
No endpoint may return another tenant's data.
18. Idempotency
Required for:
Order creation
Payment callbacks
Webhook processing
Support
Idempotency-Key
header where appropriate.
Prevent duplicate processing.
19. Webhook Standards
Always verify signatures.
Log webhook events.
Return HTTP 200 only after successful validation.
Retry failed processing using queues.
Never process webhooks synchronously if long-running.
20. Rate Limiting
Apply limits to:
Authentication
Public APIs
AI endpoints
Webhook endpoints
7
Sensitive operations
Return
429
when exceeded.
21. API Versioning
Current
v1
Future
v2

24. Performance
Enable pagination.
Avoid N+1 queries.
Select only required fields.
Use indexes.
Queue expensive operations.
Cache read-heavy endpoints when appropriate.
25. External Integrations
Wrap all third-party APIs in adapter services.
Never expose external API responses directly.
Normalize responses before returning them.
Supported integrations include:
WhatsApp Cloud API
WooCommerce REST API
Email provider
AI provider•

26. API Design Rules
Controllers
Receive request
Validate input
Call service
Return response
Controllers must not contain business logic.
Services
Contain application logic.
Repositories
Contain database access only.
External APIs
Must be accessed through integration adapters.
